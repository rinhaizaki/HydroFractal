# Гидрофрактал — веб-версия

Сайт и рабочий веб-инструмент, сделанный на основе репозитория
[HydroFractal](https://github.com/rinhaizaki/HydroFractal). Настольное приложение
на Python/Tkinter переделано в полноценный сайт: расчёты по-прежнему выполняются
тем же ядром, но интерфейс работает в браузере, без установки Python пользователем.

## Что умеет

**Режим «Снимок реки»**
- загрузка JPG/PNG/TIFF (в том числе 16-битных — значения нормализуются по 1–99 перцентилю);
- клик по руслу задаёт створ и эталон цвета в HSV;
- три способа выделения воды, допуск, дополнительные точки цвета;
- ластик, кисть, сброс выделения;
- скелет / контур / заполненная маска как объект расчёта;
- фрактальная размерность **D = 1 + h/2** методом Кантора, таблица n/ε/N,
  график log N(ε) от log(1/ε), R² и оценка Cv/Cs/Q по D.

**Режим «Карта и водосбор»**
- спутниковый слой Esri World Imagery и OpenTopoMap;
- панорамирование, масштабирование колесом к курсору, переключение слоёв;
- тайлы рельефа AWS Terrain Tiles (кодировка terrarium), SRTM ~30 м;
- заполнение впадин, направления стока D8, накопление стока, водосбор, главное русло,
  порядок Стралера;
- расчёт D по главному руслу и общий PDF-отчёт.

**Отчёт PDF** формируется на сервере: параметры, метрики, полная таблица измерений,
график, характеристики стока и снимок/карта с результатами.

## Запуск

```bash
python3 -m pip install -r requirements.txt
python3 app.py
```

Откройте `http://localhost:5000`. Сервер слушает `0.0.0.0:5000`, поэтому сайт
доступен и через live preview платформы.

## Структура

```
hydrofractal_web/
├── app.py                     # Flask: страница, API, PDF, мозаика тайлов
├── core/
│   ├── hydro_core.py          # чистые функции из river_fractal.py (без Tkinter)
│   └── map_core.py            # исходное ядро карты и гидрологии
├── static/
│   ├── index.html             # сайт + интерфейс инструмента
│   ├── styles.css             # палитра и адаптивная вёрстка
│   └── app.js                 # холсты, карта, API, выгрузка отчёта
├── requirements.txt
└── tile_cache/                # кэш тайлов создаётся автоматически
```

Математика не изменена: `core/hydro_core.py` содержит функции `segment_water`,
`boundary_mask`, `skeleton_mask`, `cantor_squares_dimension`,
`stream_stats_from_D` и др., перенесённые из оригинального `river_fractal.py`.
`core/map_core.py` — копия оригинального картографического ядра. Вместо Tk
используются HTML canvas и серверные endpoint-ы; вместо Tinos в PDF используется
DejaVu Sans (метрически близкий шрифт с кириллицей).

## REST API

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/upload` | нормализация загруженного снимка |
| POST | `/api/segment` | сегментация воды по точке-створу |
| POST | `/api/analyze` | расчёт D по маске (Кантор) + stream stats |
| POST | `/api/map/view` | мозаика тайлов карты под текущее окно |
| POST | `/api/map/analyze` | водосбор, русло, D по карте |
| POST | `/api/report` | генерация PDF |

## Ограничения

- Для расчёта нужна сеть: тайлы карты и рельефа скачиваются с внешних сервисов
  и кэшируются в `tile_cache/`.
- Разрешение рельефа — родные ~30 м (зум ЦМР ограничен 12). Узкие ручьи 3–5 м
  в такой сетке не различаются.
- Метод Кантора откалиброван на разветвлённых речных сетях; для одиночного русла
  возможна завышенная оценка D.
- В оригинальном репозитории отсутствовали `map_app.py` и папка `fonts/`;
  веб-версия не зависит от них.

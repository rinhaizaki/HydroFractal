# Гидрофрактал — веб-версия приложения

Полноценная веб-версия настольной программы [HydroFractal](https://github.com/rinhaizaki/HydroFractal):
та же структура интерфейса (меню, три панели инструментов, вкладки, холст, панель
результатов со отчётом и графиком, статус-бар), но работает в браузере.

Это **не сайт-презентация**, а рабочее приложение: все расчёты выполняются тем же
вычислительным ядром, что и в оригинальном Python/Tkinter-коде.

## Структура интерфейса

- **Меню**: Файл (загрузка/закрытие снимка, сохранение маски и PDF), Правка
  (undo/redo, очистка маски, сброс масштаба), Вид (режимы отображения, карта
  просмотра), Справка.
- **Три строки инструментов** (как в оригинале): способ выделения и допуск;
  инструменты мыши, размер кисти, undo/redo, объект расчёта; поворот/отражение,
  число делений сетки, масштаб и мини-карта.
- **Вкладка «Фотоснимок»**: холст, кнопки «Выделить реку», «Рассчитать D»,
  «Сохранить маску (PNG)», «Сохранить отчёт (PDF)», поле масштаба, текстовый
  отчёт и график log N(ε).
- **Вкладка «Карта и водосбор»**: слои Esri/OpenTopoMap, отмывка рельефа,
  панорамирование и зум (кнопки 🔍+/🔍− и колесо), мини-карта, поиск по координатам
  (только центрирование, без постановки створа), створ, водосбор, главное русло,
  морфометрия, D, отчёт. Предварительная область водосбора показывается синим,
  уточнённый водосбор — оливковым; оба слоя сохраняются в PDF. Центр карты
  по умолчанию — Санкт-Петербург.
- **Статус-бар**: подсказки инструментов, координаты курсора и ход выполнения.

## Возможности

**Снимок**
- JPG/PNG/TIFF, включая 16-битные (нормализация по 1–99 перцентилю);
- кнопка «Попробовать на примере» загружает синтетический снимок реки без файла;
- створ задаёт эталон цвета в HSV; три способа сегментации и дополнительные точки;
- ластик, кисть, undo/redo (Ctrl+Z / Ctrl+Y), поворот/отражение снимка вместе
  с маской и точками;
- zoom до 12× к курсору, панорамирование, мини-карта, три режима просмотра;
- маска сохраняется в PNG: чёрная река на белом фоне + метаданные (разрешение,
  масштаб, источник, число пикселей воды, створ, дата);
- D = 1 + h/2 методом Кантора, таблица n/ε/N, R², Cv/Cs и кривая обеспеченности.

**Карта**
- Esri World Imagery и OpenTopoMap, рельеф AWS Terrain Tiles (SRTM ~30 м);
- заполнение впадин, D8, накопление стока, водосбор, главное русло, Стралер;
- расчёт D по главному руслу и сводный PDF-отчёт.

## GitHub Pages

Готовый сайт: **https://rinhaizaki.github.io/HydroFractal/**

GitHub Pages отдаёт только статические файлы, поэтому на этой странице
вычисления выполняются прямо в браузере (`static/client-core.js`) — сервер
не нужен. Сохранение PDF открывает окно печати браузера («Сохранить как PDF»).
Отчёт повторяет формат приложенного эталона: разделы I–VII, таблицы 1–5,
рисунки 1–4, формулы (1)–(11), альбомная страница с вероятностной сеткой.
Тайлы спутника/топокарты в статическом режиме вставляются как обычные `<img>` —
им не нужен CORS, поэтому карта отображается даже там, где `fetch` к внешним
серверам запрещён. Для спутника есть цепочка резервных источников (Esri → Google
Satellite → OpenStreetMap) с таймаутом на каждый запрос; подпись внизу карты
показывает, какой источник реально загрузился. Для высот используется CORS-доступный хост S3; если он
недоступен, включение «Рельеф» показывает синтетическую отмывку, а водосбор
считается по демо-рельефу.

Локально можно запустить и серверную версию (она считает тем же ядром на Python):

```bash
python3 -m pip install -r requirements.txt
python3 app.py
```

Откройте `http://localhost:5000`. Сервер слушает `0.0.0.0:5000`, поэтому сайт
доступен и через live preview платформы.

## Структура файлов

```
app.py                     Flask: страница, API, PDF, PNG-маска с метаданными
requirements.txt           зависимости
.gitignore                 кэш тайлов и __pycache__
core/hydro_core.py         функции из river_fractal.py без Tkinter
core/map_core.py           оригинальное ядро карты и гидрологии
core/offline_map.py        демо-подложка и рельеф, если нет доступа к тайлам
static/index.html          разметка интерфейса приложения
static/styles.css          стили, панели, адаптивность
static/app.js              вся логика: холст, инструменты, карта, API, отчёты
tile_cache/                кэш тайлов создаётся автоматически
```

## REST API

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/upload` | нормализация загруженного снимка |
| POST | `/api/segment` | сегментация воды по точке-створу |
| POST | `/api/analyze` | расчёт D по маске (Кантор) |
| POST | `/api/mask/png` | маска-подложка PNG с метаданными |
| POST | `/api/map/view` | мозаика тайлов под окно карты |
| POST | `/api/map/analyze` | водосбор, русло и D по карте |
| POST | `/api/report` | PDF-отчёт |

## Ограничения

- Тайлы карты и рельефа скачиваются из сети и кэшируются в `tile_cache/`. Если сеть
  недоступна, карта переключается в демо-режим: локально генерируется местность с
  руслом, а водосбор и D считаются по этому рельефу тем же конвейером D8/Кантор;
  в интерфейсе это помечается как «демо-рельеф (нет сети)».
- Разрешение рельефа — родные ~30 м, зум ЦМР ограничен 12.
- Метод Кантора откалиброван на разветвлённых реках; для одиночного русла
  возможна завышенная оценка D.
- В оригинальном репозитории отсутствовали `map_app.py` и `fonts/`; веб-версия
  от них не зависит, в PDF используется DejaVu Sans.
